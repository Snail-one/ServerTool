# 删除与清理审查

本次审查覆盖配置清理、全部清理、数据目录删除、备份与旧备份清理、程序卸载、Go 卸载与安装残留清理、容器删除、容器资源清理及 Docker/Podman 卸载入口。验证使用临时目录和模拟命令，没有对实际服务器配置、服务或容器执行删除。

## 已修复的问题

| 范围 | 原问题 | 当前处理 |
| --- | --- | --- |
| Docker 配置 | 单凭字段名删除日志和代理设置，无法区分手动配置 | 新写入配置保存 SHA-256 归属记录；记录缺失或内容不符时停止，保留文件 |
| UPS 无首次备份场景 | 单凭常见节名和指令判断归属 | 要求有效写入记录；有首次备份时仍按确认范围恢复原配置 |
| SSH 自定义配置 | 检测到工具标记后清空整份文件 | 只删除完整托管区块，保留区块外指令；预检 Include 和自定义文件后再修改 |
| Bash、Vim、tmux、代理、SSH 公钥、Go PATH | 宽松正则可能跨越重复或损坏的标记 | 清理及替换区块前验证标记唯一、成对、顺序正确并独占一行 |
| 代理与官方 Go 环境 | 删除整行可能连带移除其他 Shell 命令或 PATH 项 | 保留复合命令；混合 PATH 仅移除精确匹配的 Go 路径 |
| 递归删除 | 软链接检查不能覆盖 bind mount 等挂载情况 | 拒绝不明确路径、公共系统目录及含挂载点的删除范围；内部软链接不跟随 |
| 全部配置清理 | 前一项失败后仍继续后续清理；最终删除未沿用确认前目录身份 | 首次失败即停止；全部配置成功后，按确认前的目录身份删除数据 |
| 备份清理 | 文件名只要包含 `.bak.` 就会被纳入；UPS 独立入口未沿用确认快照 | 常规历史备份需符合工具时间戳格式；UPS 删除也复用清单和文件身份复核 |
| Go 版本与残留 | 原始递归删除、宽松前缀及固定 `.current.tmp` 可能误伤同名文件 | 校验路径、类型、数字后缀、托管版本标记及确认前身份；切换改用随机临时链接 |
| SSH 公钥选择操作 | 确认后可能覆盖期间新增的公钥 | 删除或替换前比对原文件内容；变化时停止 |
| 单个容器删除 | 按可重复使用的名称删除 | 使用选定容器的 ID，不强制删除运行中容器 |
| 程序卸载 | 自定义安装目标可能指向其他文件或被替换 | 校验目标身份、普通文件类型、规范目录及前后文件身份；拒绝软链接目标 |

Docker/UPS 的归属记录位于统一数据目录中的模块目录，不会向原生配置格式添加未知字段。记录不作为普通历史备份删除；对应配置清理完成后移除记录。记录保存失败时停止新的配置写入。

## 保留的明确删除范围

- “清理全部本工具配置”经一次确认后，先处理配置，全部成功才删除整个 `/var/lib/snailtool`。目录内的其他文件也在确认范围内。
- 独立“删除软件数据目录”和卸载时明确同意删除数据，都会删除整个目录。卸载默认保留数据。
- 防火墙清理只删除 `inet snail` 表，不执行全局 `flush ruleset`。恢复首次快照会覆盖接入后的文件修改，确认页面已说明。
- 旧位置备份只能按独立清单确认删除；路径与名称不能单独证明历史归属，仍须核对清单。
- 容器资源清理和运行时完全卸载仍会按确认页面列出的范围删除真实数据。命名卷、运行时存储、用户配置等不能与工具自身数据目录混为一谈。

## 失败与兼容性

无法确认的旧 Docker/UPS 配置会保留并报错，避免将用户配置当成工具数据。已完成的配置清理不自动回滚；目录删除遇到 I/O 错误可能部分完成，错误会明确说明，不能将失败当作完整清理成功。

这些检查覆盖正常操作和测试中的替换、软链接、挂载边界与锁占用，不构成对其他特权进程恶意并发修改文件系统的绝对保证。

## 验证

回归测试覆盖畸形标记、保留手动内容、缺少归属记录、确认期间替换、备份锁占用、挂载点解析、陌生卸载目标、稳定容器 ID，以及取消操作。运行 `go test -count=1 ./...`；安装脚本另通过 `sh -n scripts/install.sh` 检查。
